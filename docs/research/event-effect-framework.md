# Event and effect framework research

Reference: Pokémon Showdown commit
`b79ce06d06b8f0dc8de8bb348bc9cab5d931553f`, Champions mod,
`gen9championsvgc2026regmc`.

## Source paths

- `sim/battle.ts` — `comparePriority`, `runEvent`, `resolvePriority`, and
  `priorityEvent` define handler collection, ordering, relay values, early
  termination, and default effect-type sub-orders.
- `sim/battle-actions.ts` — move execution supplies the initial hook sequence,
  including `BeforeMove`, `TryHit`, `ModifyDamage`, `Hit`, `AfterDamage`, and
  `AfterMove` behavior.
- `sim/battle.ts` and `sim/battle-actions.ts` — switching, fainting, and the
  residual request path establish the first non-move lifecycle hook sites.

## Implemented slice

`EffectRegistry` stores stateless Rust callbacks outside `BattleState` so
battles remain cloneable and serializable. At dispatch, the registry discovers
matching active abilities, items, major statuses, field/side/volatile
conditions, and the current move from typed authoritative state.

Collected handlers use Showdown's normal ordering directions: lower explicit
order, higher priority, higher holder Speed, lower sub-order, then stable
registration order. Default sub-orders distinguish conditions, field and side
conditions, abilities, and items. Dispatches carry a typed relay value, may be
cancelled, and retain the ordered invocation list for diagnostics.

Each event declares an enforced contract. `BeforeMove`, `TryHit`, and
`SwitchOut` are cancellable. Modifier events accept mutable integer relays,
while `AfterDamage` exposes read-only damage. Other lifecycle hooks accept no
relay. Wrong relay types, illegal cancellation, and out-of-range values at an
integrated call site return `InvalidState` and roll back the enclosing queue or
turn operation.

Handlers are collected and ordered once before the first callback. A handler
removed by an earlier callback remains eligible for that dispatch, while later
dispatches observe the updated state. This makes mutation behavior explicit
and prevents mid-event re-sorting.

Turn resolution currently emits `BeforeTurn`, move, damage, switch, faint, and
`Residual` dispatches. `ModifyDamage` is the first modifying relay integrated
into combat. Existing `resolve_turn` callers automatically compose the common
condition handlers; `resolve_turn_with_effects` adds caller-owned behavior
callbacks transactionally.
`ModifyAttack`, `ModifyDefense`, and `ModifyBasePower` are typed reservations;
they remain undispatched until a concrete move, ability, or item needs those
damage stages.

The focused fixture at `data/fixtures/differential/event-order.json` is
generated by `tools/showdown-reference/event-order.cjs` through the pinned
Showdown `Battle.comparePriority` function. Rust compares all ordering keys
against those results, including Showdown's default-last order and stable
effect-order tie-break.

## Deferred behavior

Later mechanics will register concrete move, ability, and item callbacks. More
specialized Showdown event relations (`onSource`,
`onAlly`, `onFoe`, and similar), priority-event first-result behavior, duration
end-callback ordering for field/side effects, and generation-specific
exceptions remain deferred until a reachable Regulation M-C mechanic requires
them. These cases must be added explicitly, not approximated through a generic
callback.
